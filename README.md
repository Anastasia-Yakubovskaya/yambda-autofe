# Automated Feature Engineering for Recommendation Ranking

Исследовательский проект по автоматизации построения признаков для рекомендательной системы на датасете **Yambda**.

Цель работы — проверить, можно ли уменьшить объём ручного feature engineering и получить качество, сопоставимое с сильным LightGBM на вручную построенных признаках.

## Что исследовалось

В работе сравниваются:

- ручные агрегированные признаки;
- расширенный пул признаков с разными временными окнами;
- автоматический отбор признаков с помощью RFE;
- автоматическая генерация признаков;
- графовые признаки;
- sequence / Transformer-модель;
- collaborative filtering;
- более реалистичная оценка с отрицательными кандидатами.

Основная метрика — **NDCG@10**.

## Основные результаты

Пример из кривой обучения при максимальном размере обучающей подвыборки (запуск с параметром N=3000; фактически 2468 пользователей имели события в 60-дневном окне):

| Подход | Число признаков | NDCG@10 |
|---|---:|---:|
| Manual | 18 | 0.7557 |
| Pool | 90 | 0.7802 |
| RFE | 18 | 0.7783 |

Автоматический отбор позволил сократить набор примерно в 5 раз почти без потери качества относительно полного пула.

Дополнительно установлено, что:

- сложная автоматическая генерация признаков не дала устойчивого улучшения относительно сильного feature pool;
- SVD-графовые признаки в основной постановке не дали устойчивого прироста; в отдельной расширенной постановке коллаборативные признаки со снимками по неделям дали небольшой общий прирост (+0.0015 NDCG@10 на тесте) и более заметный эффект на новых для пользователя кандидатах;
- sequence-модель самостоятельно уступила LightGBM;
- collaborative filtering дал небольшой общий прирост и оказался особенно полезен для новых user-item пар.

Главный вывод: наиболее практичным оказался не полный отказ от агрегированных признаков, а автоматизация их генерации и отбора.

## Данные и эксперимент

Используется открытый датасет **Yambda**. Для ускорения экспериментов используются подвыборки пользователей с сохранением полной истории выбранных пользователей.

Разбиение выполняется по времени. Признаки для каждого события рассчитываются только по прошлой истории, чтобы избежать утечки информации.

Большие датасеты, parquet-файлы, feature matrices и model caches в репозиторий не включены.

## Ноутбуки

- `01_baseline_and_feature_pool.ipynb` — подготовка данных, baseline, ручные и расширенные признаки.
- `02_feature_search_and_graph.ipynb` — автоматический поиск, RFE и графовые признаки.
- `03_extended_experiments.ipynb` — feedback, sequence/Transformer и дополнительные эксперименты.
- `04_negative_candidates.ipynb` — реалистичные отрицательные кандидаты и collaborative filtering.
- `05_autofe_search.ipynb` — финальный эксперимент по автоматической генерации и проверке признаков.

## Запуск

```bash
pip install -r requirements.txt
```

Ноутбуки в архиве очищены от outputs и execution counts. Численные результаты длительных запусков сохранены в `results/`. Исходные данные, промежуточные parquet-кэши и автоматически создаваемые файлы состояния в архив не включены; для полного повторного запуска нужно получить исходный Yambda-50M и выполнить ноутбуки по порядку. Архив содержит журналы результатов, но не является автономным набором данных.
